# Session Summary — 2026-04-01 23:24

## Bugs Fixed

### Bug 1: KML Tour had no animated mower markers

**Problem:** The `--kml-tour` output was a camera-only flyover — the camera flew along mower 1's path but no mower marker was visible. The user expected to see mower 1 moving with the camera following behind it.

**Root cause:** `generate_kml_tour()` in `kml.py` only generated static `LineString` placemarks and a `gx:Tour` camera flyover. No `gx:Track` elements were included, so there were no animated markers.

**Fix:** Added `gx:Track` placemarks for ALL mowers to the tour KML, with synthetic timestamps (distance-based at 1 m/s). The camera `gx:FlyTo` durations are now synchronized with mower 1's track timestamps so the camera follows the moving mower marker. The tour KML now contains:
- Static `LineString` placemarks (path visualization)
- Animated `gx:Track` placemarks (moving mower markers)
- `gx:Tour` with `gx:FlyTo` playlist (camera following mower 1)

**File:** `src/nav_planning/kml.py` — `generate_kml_tour()`

### Bug 2: Contour paths had consecutive duplicate waypoints

**Problem:** Mower 1's path for `input/37_long.kml` had 20 waypoints instead of the expected 11, with every intermediate vertex duplicated (e.g., `[A, B, B, C, C, D]`). This caused duplicate waypoints in `.waypoints` files and duplicate FlyTo entries in the tour KML (with heading=0 artifacts at duplicate positions).

**Root cause:** `_extract_coords()` in `contour.py` concatenated coordinates from `MultiLineString` segments without checking for shared endpoints. When `polygon.intersection(spine_line)` clips at polygon vertices, each segment shares its endpoints with neighbors.

**Fix:** Added consecutive deduplication to `_extract_coords()` — when iterating MultiLineString segments, skip a coordinate if it matches the last one already collected.

**File:** `src/nav_planning/contour.py` — `_extract_coords()`

**Before/After for `input/37_long.kml` mower 1:**
- Before: 20 waypoints (9 consecutive duplicates)
- After: 11 waypoints (clean, matches KML spine vertices exactly)
