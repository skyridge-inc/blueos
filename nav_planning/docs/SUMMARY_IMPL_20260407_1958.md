### 3. Fixed a delta-operator bug

`replace-boustrophedon-with-contour-paths/specs/mow-planning/spec.md` declared
its three new requirements under `## MODIFIED Requirements`, but those
requirement *headers* never existed in the canonical spec — only the
soon-to-be-removed `Boustrophedon Path Generation` did. The archive step
aborted with:

```
mow-planning MODIFIED failed for header
"### Requirement: Contour-Following Path Generation" - not found
```

**Fix**: changed the operator from `## MODIFIED Requirements` to
`## ADDED Requirements` in that delta file. The `## REMOVED Requirements`
section (which removes Boustrophedon and Auto-Heading Detection) was left
untouched. After the fix, validation passed and the archive applied
**+3 / -2** as expected.

`★ Why this matters`: OpenSpec treats requirements as named records, not
floating concepts. `MODIFIED` is a header-text lookup; introducing a
"replacement" requirement under a new name is an `ADDED` op, even when paired
with a `REMOVED` op for the predecessor. Conflating concept-evolution with
header-continuity is a recurring authoring pitfall.
